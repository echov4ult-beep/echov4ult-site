Why I rebuilt echov4ult as a project universe

The old homepage sold three kits. The new one has to explain the builder, connect the projects, and give every visitor a useful door into the work.

By Chris Retherford · 8 minute read

I had a website full of finished work that still made me look like I only sold AI kits.

Full Party, Operator's Kit, and Launch Crew deserved a place on the homepage. They were shipped products with free demos and working pages. But they were not the whole story. I was also building ViralLens, making small games, writing field notes, running agent teams, and turning my own workflows into tools.

The homepage had flattened all of that into a three-product shelf.

The site had the wrong center of gravity

The first version asked visitors to pick a kit before they understood who built it or why the projects belonged together. The navigation reinforced the same idea: three product names, then guides and a blog.

That structure works for a small store. It does not work for a personal brand built around many projects.

The new center is simple: I build ambitious things with AI crews. The kits are proof. ViralLens is proof. V4ULT RUN is proof. The articles are the notebook beside the workbench.

The useful mistake happened first

I initially audited the wrong domain.

Echov4ult Web is a separate local website service at echov4ultweb.com. The personal brand lives at echov4ult.com. Both domains were live, both had project files on the same Mac, and I followed the business context instead of resolving the domain before planning.

No production files were changed, but the mistake produced a complete plan for the wrong site. I deleted that plan, logged the failure, verified both domains, and restarted.

That became a design requirement: the public site should make its identity obvious within seconds.

One visual idea carried the rebuild

I kept the terminal-noir identity because it already belonged to Echov4ult. The redesign added one signature element: a project constellation with Echov4ult at the center and each public project orbiting it.

The rest of the homepage supports that map:

  • Six project surfaces with honest state labels such as Shipped, Active Lab, Playable, and Open Notes.
  • A house-method panel that shows how the projects move from mission to review to receipts.
  • A recent-transmissions section for writing from inside the work.
  • An entry console that routes visitors by what they want to build.

I deliberately avoided turning the public homepage into a copy of my private venture dashboard. The private dashboard answers what needs my attention. The website answers who I am, what I have made, and where a visitor can experience it.

The repositories behind the process

The homepage itself is plain HTML, CSS, and JavaScript. The design and verification process used instruction sets from several public repositories:

  • Vercel Agent Skills for interface review and React guidance. The React rules were correctly skipped because this site is static.
  • Web Interface Guidelines for focus, form, motion, content, and interaction checks.
  • Web Quality Skills for performance, accessibility, Core Web Vitals, SEO, and browser-quality gates.
  • Design Systems to Agent Skills as the future path for turning a maintained component system into project-specific agent knowledge.
  • Anthropic's Frontend Design skill for the art-direction pass.

The public site source is also available at github.com/echov4ult-beep/echov4ult-site.

The quality gate changed the design

The first live baseline scored 84 for performance and 89 for accessibility in one mobile Lighthouse lab run. It also showed a 3.04-second LCP and a CLS of 0.119.

The redesign exposed a more important behavior problem. Scroll-reveal CSS made most sections invisible until JavaScript and IntersectionObserver activated. A human scrolling normally would see the content, but full-page captures and some automated browsers saw a mostly empty page.

I removed opacity-based hiding. Animation now sits in the constellation, hover states, diagrams, and surface depth. The content stays visible with JavaScript disabled and when reduced motion is enabled.

The final local run scored 99 performance and 100 in accessibility, best practices, SEO, and agentic browsing. LCP measured 1.57 seconds, CLS measured 0.002, and total blocking time remained zero. Those are lab values, not a claim about every visitor, but they are a much better starting point.

What the new homepage is allowed to become

The project universe can grow without forcing every project into the navigation. A project earns a public card when it has a clear job, an honest state, and something a visitor can experience.

That rule matters because I build more things than I should publish. The website is the edited record, not the entire workshop floor.
