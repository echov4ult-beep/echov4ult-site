What are Claude Code subagents?

2026-07-26 · echov4ult

The thirty-second answer, the five-minute answer, and the judgment call the docs won't make for you.

Claude Code subagents are specialized AI assistants defined as markdown files — each with its own system prompt, its own context window, and optionally its own restricted tool set — that the main Claude Code session can delegate tasks to. You describe when each subagent should be used; Claude Code routes matching work to it and gets the result back.

How they work, mechanically

A subagent lives in .claude/agents/ in your project (or user-level for all projects). The file has frontmatter — a name, a description of when to use it, optional tool permissions — followed by a system prompt that defines its role. When the main session decides a task matches, it hands the task over; the subagent works in a separate context window and reports back a result.

Two properties do most of the work:

  • Context isolation. The subagent doesn't inherit the main conversation's clutter, and its own exploration doesn't pollute yours. A research subagent can read thirty files and return three sentences.
  • Scoped permissions. A reviewer that can read but not edit. A test-runner that can execute but not install. Restriction is a design tool, not a limitation.

When subagents earn their overhead

  • Verdict roles — reviewer, QA, critic — where independence from the main session's assumptions is the entire value.
  • High-volume reading — sweep tasks whose intermediate output would drown your main context.
  • Repeatable specialist work — the same role, invoked the same way, across sessions and projects.

When they don't

Delegation costs tokens and adds a hop: the subagent starts cold and must be briefed by prompt. For quick, deeply contextual work — a small fix in a file you've been discussing for an hour — the main session already holds the context, and a subagent is overhead cosplaying as architecture. One well-placed agent beats five decorative ones. (More on right-sizing: small party vs. mega-roster.)
